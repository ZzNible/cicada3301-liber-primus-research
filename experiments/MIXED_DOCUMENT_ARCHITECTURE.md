# Liber Primus as a mixed document architecture

## Why change the question?

A common implicit model is:

> the unresolved rune body is one homogeneous ciphertext generated by one main cryptographic mechanism.

The accumulated evidence does not justify making that the unique working model.

EXP-462 therefore compared broader functional interpretations and concluded that a **mixed data-plane + control-plane architecture** best integrates the current evidence.

**Status: SIGNAL / favored architecture. Mechanism: OPEN.**

This is a research framing, not a decoded control channel.

## Evidence that motivates the model

Several observations live naturally in different functional layers.

### Semantic/content layer

Solved Liber Primus contains meaningful prose and source-defined semantic roles. Selected `WARNING`, `WISDOM`, `INSTRUCTION` and `PARABLE` statements show a strong prime-GP convention.

Prime-GP therefore looks more like a downstream semantic verifier than a direct ciphertext transform.

### Structural/meta layer

EXP-451 found that red rubrication does **not** directly mark prime-GP content. Instead, solved red spans repeatedly occur on titles, subsection labels, framing labels, enumeration/control markers and boundaries.

Examples include:

- `THE LOSS OF DIVINITY`
- `CONSUMPTION`
- `PRESERVATION`
- `ADHERENCE`
- `SOME WISDOM`
- `AN INSTRUCTION`
- `KNOW THIS`
- `AN END`
- `PARABLE`

This supports a possible complementarity:

`rubrication -> structural/meta framing`

versus

`prime-GP -> selected semantic content statements`

### External verification / handoff layer

`AN END` supplies a fixed 512-bit verifier for an external page while leaving its locator and exact representation unresolved.

That behavior is naturally interpreted as a handoff/verification function rather than ordinary local prose decryption.

### Ciphertext/generated-object layer

The unresolved rune stream has a strong adjacent-repeat suppression (`K=86`) without an identified mechanism. Several simple local explanations fail.

This is compatible with generated or constrained data, but does not tell us whether every symbol participates in one uniform plaintext cipher.

## EXP-462 conclusions

The closure audit made several useful scope corrections.

- **REJECTED scoped framing:** the research problem can safely be reduced to one simple/fixed classical cipher or one uniform local-state mechanism.
- **REJECTED modeling assumption:** layout, rubrication and marker information can simply be ignored as decorative in a lossless functional model.
- **REJECTED inference:** failure to recover plaintext is evidence that LP2 is deliberate filler or decoy.
- **OPEN:** direct meaningful plaintext remains possible as one component.
- **SIGNAL:** a mixed content/control/verification architecture is a better integrative working model.

## What this does NOT authorize

The mixed architecture must not become an excuse for unconstrained invention.

It does not license:

- reading red/black as arbitrary binary bits;
- inventing page selectors;
- choosing reset boundaries after seeing favorable outputs;
- turning punctuation into a custom alphabet;
- assigning numeric markers to states post hoc;
- mining offsets until English appears.

A control layer becomes evidence only when its grammar is fixed independently and makes a prediction.

## A different future experiment

The strongest unfinished idea is not another cipher sweep. It is to model Liber Primus as a **document protocol**.

One possible falsifiable program is:

1. derive a finite functional-role grammar from solved material only;
2. use only non-semantic observable features such as rubrication, punctuation, section boundaries and layout to classify structural roles;
3. freeze the classifier before applying it to unresolved pages;
4. publish the predicted role map before any future decryption;
5. score that map against future independently recovered plaintext/structure.

This would turn the layered-document idea into a set of predictions rather than a narrative.

## Current status

- homogeneous single-mechanism assumption: **not justified as unique model**
- mixed document architecture: **SIGNAL / favored working model**
- hidden control channel: **OPEN, not established**
- rubrication as structural/meta layer: **SIGNAL**
- rubrication as direct prime marker: **REJECTED scoped**
- prime-GP as semantic downstream verifier: **SIGNAL STRONG**
- external AN END verifier/handoff role: **ESTABLISHED structural fact / mechanism OPEN**

The useful conceptual shift is simple:

> ask not only “what does this rune decrypt to?” but also “what function does this part of the document perform?”
